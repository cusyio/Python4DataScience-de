Umgebungen trennen
==================

Aktuelle Best-Practices trennen zwischen verschiedenen Umgebungen, je nachdem,
was in dieser Umgebung gemacht werden soll. So wird :abbr:`z. B. (zum Beispiel)`
in unserer `cusy.tasks <https://github.com/cusyio/cusy.tasks>`_-Anwendungen
folgende Umgebungen unterschieden:

.. code-block:: toml
   :caption: pyproject.toml

   [project]

   dependencies = [
     "rich",
     "tinydb",
     "typer",
   ]

   [dependency-groups]
   dev = [
     "pre-commit",
     "reuse",
     "tox-uv",
     "watchgha",
     { include-group = "docs" },
     { include-group = "tests" },
   ]
   docs = [
     "furo",
     "interrogate",
     "matplotlib",
     "sphinx-copybutton",
     "sphinx-inline-tabs",
     "sphinxcontrib-napoleon",
     "sphinxext-opengraph",
   ]
   tests = [
     "coverage[toml]",
     "faker",
     "pytest",
     "pytest-cov",
   ]

So können beim Betrieb der Anwendung nur die dafür benötigten Abhängigkeiten
installiert werden, Nur beim Testen oder beim Deployment der Dokumentation
werden jeweils dort benötigte Abhängigkeiten zusätzlich installiert. Lediglich
die Entwicklungsumgebung enthält alle Abhängigkeiten.

So wie eure Python-Umgebung mit unveränderbaren Referenzen aktuell gehalten
werden sollte, sollten auch eure
:doc:`../git/advanced/hooks/checks` und GitHub Actions regelmäßig aktualisiert
werden.

In der :file:`.pre-commit-config.yaml` sollten die Versionen der Checks mit
ihren Hashes regelmäßig aktualisiert werden, :abbr:`z. B. (zum Beispiel)` mit:

.. code-block:: console

   $ uv run prek update --freeze --cooldown-days 7
   https://github.com/pre-commit/pre-commit-hooks
     updating rev `v6.0.0` -> `3e8a8703264a2f4a69428a0aa4dcb512790b2c8c` (frozen: v6.0.0)

.. seealso::
   :doc:`../git/advanced/hooks/prek`

Überprüft eure GitHub-Actions
-----------------------------

Da GitHub-Actions aus :doc:`Git <../git/index>` abgerufen werden, empfiehlt
sich, einen vollständigen SHA anstelle eines Tags anzugeben, da Tags geändert
werden können und anfällig für Supply-Chain-Angriffe sind.

.. _pinact:

pinact
~~~~~~

Für GitHub-Actions könnt ihr `pinact
<https://github.com/suzuki-shunsuke/pinact>`_ verwenden, :abbr:`z. B. (zum
Beispiel)` mit

.. code-block:: console

   $ pinact run --update --min-age 7

Dies aktualisiert die GitHub-Actions, jedoch mit einem siebentägigen Cooldown.

.. _gh-actions-lock:

gh-actions-lock
~~~~~~~~~~~~~~~

`gh-actions-lock <https://github.com/github/gh-actions-lock#install>`_ geht
darüberhinaus und schreibt auch die transitiven Verknüpfungen in die Datei
:file:`.github/workflows/actions.lock`. Ihr könnt ``gh-actions-lock`` mithilfe
der `GitHub CLI <https://cli.github.com/>`_ installieren:

.. code-block:: console

   $ gh extension install github/gh-actions-lock
   ✓ Installed extension github/gh-actions-lock

Anschließend könnt ihr eure GitHub Actions in eurem Repository mit folgendem
Befehl sperren:

.. code-block:: console

   gh actions-lock

GitHub empfiehlt außerdem, `Lockfiles im Rahmen der CI zu überprüfen
<https://docs.github.com/de/actions/how-tos/administer/enforce-workflow-lockfiles#a-dedicated-workflow-or-copilot>`_,
um sicherzustellen, dass sie aktuell und nicht beschädigt sind. Hierfür
erstellen wir :file:`.github/workflows/verify-lockfile.yml` mit:

.. code-block:: yaml

   # Fails when .github/workflows/actions.lock is out of sync with the
   # workflows or a locked pin no longer verifies upstream.
   lockfile:
     runs-on: ubuntu-slim
     env:
       GH_TOKEN: ${{ github.token }}

     steps:
       - uses: actions/checkout@v7.0.1
         with:
           persist-credentials: false
       - run: gh extension install github/gh-actions-lock --pin v0.4.1
       - run: gh actions-lock --verify

.. seealso::
   * `GitHub Actions workflow lockfiles are generally available
     <https://github.blog/changelog/2026-10-28-github-actions-workflow-lockfiles-are-generally-available/>`_
   * :doc:`../envs/uv/renovate` unterstützt auch
     :file:`.github/workflows/actions.lock`-Dateien:
     `Renovate CLI documentation
     <https://docs.renovatebot.com/modules/manager/github-actions/#github-actions-lockfile-actionslock>`_.

zizmor
~~~~~~

`zizmor <https://docs.zizmor.sh>`_ ist ein Tool zur statischen Analyse, das
Sicherheitslücken in GitHub-Actions-Workflows aufspürt – darunter
Template-Injection, nicht fixierte Aktionen, übermäßige Berechtigungen, das
Offenlegen von Anmeldedaten sowie `mehr als 30 weitere Prüfregeln
<https://docs.zizmor.sh/audits/>`_. ``zizmor`` erkennt Schwachstellen wie
diejenigen, die durch :ref:`token-exfiltration` ausgenutzt wurden.

Ihr könnt zizmor auch zusammen mit :doc:`../git/advanced/hooks/prek` verwenden:

.. code-block:: yaml

   - repo: https://github.com/zizmorcore/zizmor-pre-commit
     rev: 06a39750ec31860bb44f2acf67182c40016cd1e7  # frozen: v1.32.0
     hooks:
       - id: zizmor

.. seealso::
   * :ref:`zizmorcore`
